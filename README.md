# CodeReviewAgent - Intelligent Code Review Assistant

A code review agent built with LangChain 1.x, featuring code structure analysis,
basic style checks, and Markdown reports.

## How It Works

The agent is built with `create_agent`. The model selects tools and their arguments,
receives execution results, and decides whether to call another tool or return a final
report. Tool execution order is not hard-coded.

Execution is limited to 30 graph steps to prevent endless loops. This limit is not
the number of model calls.

- `ChatOpenAI` connects to the configured ModelScope / Qwen service through a
  compatible Chat Completions API.
- `@tool` exposes analysis functions as tools available to the model.
- `create_agent` manages the model, tools, and conversation loop.

HelloAgents is no longer required. The existing `LLM_*` settings are retained;
the adapter name does not require switching model providers.
Both the model and its service must support native tool calling. Chat API
compatibility alone does not guarantee tool support. Verify the example model's
availability and tool-calling support with the actual service.

## Installation and Configuration

Python 3.10 or later is required. Installing in a virtual environment is recommended.

```bash
python -m pip install -r requirements.txt
```

Copy `.env.example` to `.env` and set your `LLM_API_KEY`.

PowerShell:

```powershell
Copy-Item .env.example .env
```

macOS / Linux:

```bash
cp .env.example .env
```

| Variable | Description |
| --- | --- |
| `LLM_MODEL_ID` | Name of a model that supports tool calling |
| `LLM_API_KEY` | API key for the configured model service |
| `LLM_BASE_URL` | Base URL of the compatible model API |
| `LLM_TIMEOUT` | Positive integer request timeout in seconds; defaults to 60 |

Existing environment variables take priority over `.env`. The notebook does not
overwrite them. Do not commit `.env` files containing real API keys.
When using an external model service, the code under review is sent to that service.

## Running the Project

Start `jupyter lab` from the project root and make sure the notebook kernel uses
the same working directory. Restart an existing kernel after installing dependencies.

- **Quick demo:** Run all code cells in Part 0 in order.
- **Full review:** Run Parts 1–6 in order; Part 7 contains the summary.
  The quick demo is not a prerequisite.
- **Run all cells:** Executes both demos, each of which calls the model service.

The full workflow reads `data/sample_code.py`, asks the agent to review it, and saves
the result to `outputs/review_report.md`. The output directory is created if needed;
an existing report is overwritten.

If a request fails, the step limit is reached, or the model returns an empty report,
resolve the error and rerun the review cell before saving.

## Tools and Scope

| Tool | Purpose |
| --- | --- |
| `quick_analysis` | Quickly count classes and functions |
| `code_analysis` | Return function, class, and line counts with name lists |
| `style_check` | Check line lengths and block indentation, not full PEP 8 compliance |

Function counts include regular functions, async functions, and class methods.
Static tools parse source code without executing it. The model generates potential
bug findings, performance suggestions, and best-practice advice using the source
and tool results. These suggestions should be reviewed by a person.

Documentation and code comments are in English. Runtime messages, prompts, and the
existing sample report retain their original language.

## Troubleshooting

- **Missing API key:** Set `LLM_API_KEY` in the project root's `.env` file.
- **Input file not found:** Check the notebook kernel's working directory.
- **Service rejects the `tools` parameter:** Verify native tool-calling support and
  update the model configuration if necessary.
- **Step limit reached:** Reduce the input size or adjust the prompt. The agent does
  not automatically fall back to a fixed sequence of tool calls.
